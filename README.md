# Ре:Акция

Сайт и Telegram-бот для обращений жителей по коммунальным услугам. Оба клиента используют один backend, одну базу данных и локальную модель Qwen.

## Папки и основные файлы

- `frontend/` — готовый React-интерфейс из GitHub; `src/pages/Chat.tsx` отправляет сообщения в API.
- `backend/main.py` — API сайта и бота.
- `backend/database.py` — работа с SQLite и полнотекстовый поиск FTS5.
- `backend/migrations/` — структура базы и начальные категории/инструкции.
- `backend/rag.py` — передаёт найденный контекст локальному Qwen.
- `bot/bot.py` — готовый aiogram-бот из GitHub, подключённый к API.
- `docker-compose.yml` — запускает весь проект.

## База данных

Хранит пользователей, адреса, диалоги, сообщения, статьи базы знаний, заявки, историю статусов, вложения, оценки, объявления и показания счётчиков. Файл `support.db` создаётся автоматически и хранится в Docker volume. Статьи ищутся через SQLite FTS5, поэтому тяжёлые embedding-модели и FAISS не занимают память сервера.

## Запуск на сервере 2 CPU / 4 ГБ

1. Установите Docker и Docker Compose.
2. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN`.
3. Выполните `docker compose up -d --build`.

При первом запуске будет загружен Qwen2.5-1.5B-Instruct Q4_K_M размером около 1,12 ГБ. Сайт откроется на `http://IP_СЕРВЕРА`, документация API — на `http://IP_СЕРВЕРА/api/docs`.

Для проверки базы выполните из папки `backend`: `python -m unittest discover -s tests -v`.

## Ограничения MVP

- Стартовые регламенты помечены как демонстрационные; перед защитой их нужно сверить с реальными поставщиками.
- На двух CPU ответ Qwen может формироваться 10–40 секунд.
- Токены и секреты хранятся только в `.env`, этот файл исключён из Git.
